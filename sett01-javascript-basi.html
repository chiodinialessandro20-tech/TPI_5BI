Sezione 01

Variabili: const e let

Due parole per dichiarare una variabile. La regola pratica sta in una riga: usa sempre const, passa a let solo quando serve davvero.

La differenza

let dichiara una variabile che potrà cambiare valore. const dichiara una variabile che non potrà essere riassegnata.

let punteggio = 0
punteggio = 10        // va bene

const nome = "Sara"
nome = "Luca"         // errore!

L'errore che ottieni è TypeError: Assignment to constant variable. Provalo:

Esperimento
La regola da seguire

Dichiara sempre con const. Se a un certo punto ti serve riassegnare la variabile, allora e solo allora torni indietro e la cambi in let.

Non è pignoleria: const comunica a chi legge il codice che quel valore non cambierà mai. Meno cose possono cambiare, meno cose possono rompersi.

Attenzione: const blocca la riassegnazione, non il contenuto

Questo è il punto che confonde tutti. Con un oggetto o un array, const impedisce di sostituire l'intero valore, ma non impedisce di modificarne l'interno.

const colori = ["rosso", "verde"]
colori.push("blu")     // va bene: modifico il contenuto
console.log(colori)    // ["rosso", "verde", "blu"]

colori = ["giallo"]    // errore: sto sostituendo l'intero array

Il perché lo capirai fino in fondo alla settimana 3, quando parleremo di valori e riferimenti. Per ora tienilo come fatto: const protegge il collegamento tra il nome e il valore, non il valore stesso.

E var?

Se cerchi codice JavaScript in rete troverai spesso var. È la vecchia parola chiave, precedente al 2015. Ha regole di visibilità diverse e più confuse.

Non usare mai var

In questo corso non scriverai mai var. Se lo trovi in un esempio online, sappi che è codice datato. Sostituiscilo con const e, se necessario, con let.

Il libro di testo dà per acquisita la sintassi di base di JavaScript. Questa sezione recupera quel prerequisito e riprende gli esempi delle esercitazioni di laboratorio degli anni precedenti.

Dove vive una variabile

Una variabile dichiarata dentro una coppia di parentesi graffe esiste solo lì dentro.

Visibilità

Il secondo console.log dà ReferenceError: dentro is not defined. La variabile è nata e morta dentro le graffe. Vale lo stesso per il corpo di una funzione, di un if, di un ciclo.

Sezione 02

Tipi e confronti

JavaScript non ti chiede di dichiarare il tipo. Decide da solo, e a volte decide in modo sorprendente.

Tipizzazione dinamica

Non scrivi int o String. Scrivi il valore, e il tipo lo deduce il linguaggio.

const numero = 42          // number
const testo = "ciao"       // string
const acceso = true        // boolean
const niente = null        // null
let vuoto                  // undefined

Una stessa variabile può perfino cambiare tipo durante l'esecuzione. Puoi farlo, ma non farlo: è una fonte inesauribile di bug.

Scopri il tipo con typeof

L'ultimo risultato è "object", ed è sbagliato: null non è un oggetto. È un difetto storico di JavaScript, presente dal 1995 e mai corretto per non rompere il codice esistente. Serve saperlo, non serve capirlo.

La differenza tra null e undefined

ValoreSignificatoChi lo mette
undefinedNon c'è ancora un valoreJavaScript, in automatico
nullVolutamente vuotoTu, di proposito

Confronti: === e non ==

JavaScript ha due operatori di uguaglianza. Uno confronta il valore dopo aver convertito i tipi, l'altro confronta valore e tipo.

Guarda cosa succede
Regola secca

Usa sempre === e !==. Non c'è quasi nessuna situazione in cui == sia la scelta giusta, e ce ne sono molte in cui produce risultati che non ti aspetti.

Valori falsy

Quando JavaScript deve valutare un valore come vero o falso — dentro un if, per esempio — questi sei valori contano come falsi:

false
0
""          // stringa vuota
null
undefined
NaN         // "Not a Number"

Tutto il resto è vero. Tutto: anche "0" (la stringa contenente zero), anche un array vuoto, anche un oggetto vuoto.

Verifica
Segnalo ora perché torna

Che un array vuoto sia vero è la causa di un errore che farai di sicuro nella settimana 2. Quando cercherai qualcosa in una lista e non troverai niente, otterrai un array vuoto — e un if su quell'array entrerà lo stesso.

La forma corretta è controllare la lunghezza: if (risultati.length > 0).

Sezione 03

Template literal

Un modo per costruire stringhe senza impazzire con i +. Lo userai continuamente.

Il problema

Costruire una frase concatenando pezzi è faticoso da scrivere e da leggere:

const nome = "Sara"
const voto = 8

const frase = "Lo studente " + nome + " ha preso " + voto + " in TPSIT."

La soluzione

Usa i backtick — l'apice inclinato ` — al posto delle virgolette, e inserisci le espressioni dentro ${...}.

const frase = `Lo studente ${nome} ha preso ${voto} in TPSIT.`
Dove sta il backtick

Su tastiera italiana: AltGr + ' (il tasto dell'apostrofo, accanto al punto interrogativo). Non è l'apostrofo normale e non è la virgoletta: se sbagli tasto il codice non funziona.

Prova a modificare i valori

Dentro ${...} ci va qualsiasi espressione

Non solo variabili: calcoli, chiamate a funzione, condizioni.

Espressioni

La seconda riga usa l'operatore ternario: condizione ? valoreSeVero : valoreSeFalso. È un if compatto che produce un valore invece di eseguire istruzioni. Tornerà spessissimo, perché dentro React è l'unico modo di scrivere una condizione nell'interfaccia.

Stringhe su più righe

Con i backtick puoi andare a capo senza caratteri speciali:

const messaggio = `Prima riga
Seconda riga
Terza riga`
Sezione 04

Funzioni

Le conosci già da altri linguaggi. Qui c'è una cosa in più che cambia tutto: in JavaScript una funzione è un valore.

La forma classica

function somma(a, b) {
  return a + b
}

console.log(somma(2, 4))   // 6

Niente di nuovo: nome, parametri, corpo, return.

La funzione come valore

Questa è la novità. Una funzione può essere assegnata a una variabile, esattamente come un numero o una stringa.

Due modi, stesso risultato

Nella seconda forma la funzione non ha nome proprio: si chiama tramite la costante a cui è assegnata. Si invoca in modo identico.

Perché conta

Se una funzione è un valore, allora può essere passata a un'altra funzione come argomento. È il meccanismo su cui poggiano map, filter e reduce — cioè tutta la settimana 2 — e tutta la gestione degli eventi in React.

Parametri con valore predefinito

function saluta(nome = "ospite") {
  return `Ciao ${nome}`
}

console.log(saluta("Sara"))   // Ciao Sara
console.log(saluta())         // Ciao ospite

Una funzione che riceve una funzione

Qui il concetto diventa concreto. esegui non sa cosa farà: glielo dici tu passandogli una funzione.

Funzione come argomento
L'errore da non fare

Nota che si scrive esegui(saluta) e non esegui(saluta()).

  • saluta è la funzione stessa: la stai passando
  • saluta() la esegue subito e passa il suo risultato

Le parentesi sono la differenza tra consegnare una ricetta e consegnare il piatto cucinato. Questo identico errore ti farà perdere tempo nella settimana 7 con React: onClick={gestisci} funziona, onClick={gestisci()} no.

Il confronto tra dichiarazione ed espressione di funzione, e il concetto di funzione passata come argomento, riprendono i materiali di laboratorio degli anni precedenti.

Sezione 05

Arrow function

Una scrittura più corta per le funzioni. Sembra solo estetica: in realtà è la forma che vedrai nel 90% del codice React.

Dalla forma lunga alla forma corta

Parti dalla funzione assegnata a una costante, che hai visto nella sezione 04:

const somma = function (a, b) {
  return a + b
}

Togli la parola function e metti una freccia => dopo i parametri:

const somma = (a, b) => {
  return a + b
}

Se il corpo è una sola espressione da restituire, togli graffe e return:

const somma = (a, b) => a + b
Il return implicito

Nell'ultima forma il valore viene restituito automaticamente. È comodissimo, ma vale solo senza graffe. Se apri le graffe devi scrivere return, altrimenti la funzione restituisce undefined.

Le quattro forme a confronto

Due scorciatoie sui parametri

ParametriCome si scriveEsempio
Uno soloLe parentesi si possono ometteren => n * 2
NessunoLe parentesi vuote sono obbligatorie() => "ciao"
Due o piùParentesi obbligatorie(a, b) => a + b
Provale
Errore frequente

Se scrivi const f = (a, b) => { a + b } la funzione restituisce undefined. Ci sono le graffe, quindi serve il return. Provalo nel riquadro qui sopra: cambia area e guarda cosa succede.

Es 1

Conversione di temperatura

base

Scrivi una funzione celsiusToFahrenheit che riceve una temperatura in gradi Celsius e restituisce i gradi Fahrenheit. La formula è F = C × 9/5 + 32.

Stampa il risultato per 0, 25 e 100 gradi usando un template literal, così: 25°C corrispondono a 77°F.

Il tuo codice

La funzione ha un solo parametro e restituisce un calcolo: è il caso perfetto per una arrow function compatta senza graffe.

Per la stampa, ricorda che dentro ${...} puoi mettere anche una chiamata di funzione.

const celsiusToFahrenheit = c => c * 9 / 5 + 32

console.log(`0°C corrispondono a ${celsiusToFahrenheit(0)}°F`)
console.log(`25°C corrispondono a ${celsiusToFahrenheit(25)}°F`)
console.log(`100°C corrispondono a ${celsiusToFahrenheit(100)}°F`)
Es 2

Validazione di un voto

base

Scrivi una funzione votoValido che riceve un numero e restituisce true se è un voto ammissibile — cioè compreso tra 0 e 10, estremi inclusi — e false altrimenti.

Provala con 7, con 11, con -2 e con 0. Attenzione a quest'ultimo caso.

Il tuo codice

Non serve if: un confronto produce già true o false, e due confronti si uniscono con &&.

Il caso dello 0 è la trappola: 0 è un valore falsy, quindi se controlli il voto con un if (voto) lo scarti per sbaglio. Confronta i numeri, non la loro verità.

const votoValido = v => v >= 0 && v <= 10

console.log(votoValido(7))    // true
console.log(votoValido(11))   // false
console.log(votoValido(-2))   // false
console.log(votoValido(0))    // true

Se avessi scritto if (voto && voto <= 10), lo 0 avrebbe dato false: sbagliato.

Es 3

Esito con il ternario

base

Scrivi una funzione esito che riceve un voto e restituisce la stringa "promosso" se il voto è almeno 6, altrimenti "da recuperare".

Usa l'operatore ternario, non if. Provala con 4, 6 e 9.

Il tuo codice

Lo schema è condizione ? seVero : seFalso. Tutto il ternario è una singola espressione, quindi sta bene in una arrow function senza graffe.

const esito = voto => voto >= 6 ? "promosso" : "da recuperare"

console.log(esito(4))
console.log(esito(6))
console.log(esito(9))
Es 4

Tre livelli di esito

intermedio

Estendi l'esercizio precedente. La funzione giudizio restituisce:

  • "gravemente insufficiente" se il voto è minore o uguale a 4
  • "insufficiente" se è 5
  • "sufficiente" se è 6 o più

Puoi usare due ternari annidati oppure if. Prova entrambe le strade e decidi quale si legge meglio.

Il tuo codice

Nel ternario annidato, il ramo "altrimenti" del primo ternario è a sua volta un ternario intero. Scrivilo su tre righe, altrimenti diventa illeggibile.

const giudizio = voto =>
  voto <= 4 ? "gravemente insufficiente"
  : voto === 5 ? "insufficiente"
  : "sufficiente"

console.log(giudizio(3))
console.log(giudizio(5))
console.log(giudizio(8))

Con più di due livelli l'if classico è spesso più chiaro. Il ternario dà il meglio con due sole alternative.

Es 5

Prezzo con IVA

intermedio

Scrivi calcolaPrezzoFinale(prezzoBase, iva) che restituisce il prezzo comprensivo di IVA. L'IVA arriva come percentuale: 22 significa 22%.

Fai in modo che, se l'IVA non viene passata, valga 22 in automatico. Stampa il risultato con un template literal.

Il tuo codice

Il valore predefinito si scrive nella lista dei parametri: (prezzoBase, iva = 22) => ...

Per convertire la percentuale dividi per 100.

const calcolaPrezzoFinale = (prezzoBase, iva = 22) =>
  prezzoBase + prezzoBase * (iva / 100)

console.log(`Il prezzo finale è: ${calcolaPrezzoFinale(100)} euro`)
console.log(`Il prezzo finale è: ${calcolaPrezzoFinale(100, 4)} euro`)
Es 6

Una funzione che ne riceve un'altra

avanzato

Scrivi una funzione applicaDueVolte(valore, operazione) che applica operazione al valore, poi la riapplica al risultato, e restituisce il risultato finale.

Provala passando una funzione che raddoppia — applicaDueVolte(3, doppio) deve dare 12 — e una che aggiunge 10.

Il tuo codice

Dentro applicaDueVolte, operazione è una funzione a tutti gli effetti: la chiami con le parentesi, operazione(valore).

Quando la passi, invece, le parentesi non ci vanno: applicaDueVolte(3, doppio), non doppio().

const applicaDueVolte = (valore, operazione) => operazione(operazione(valore))

const doppio = n => n * 2
const piuDieci = n => n + 10

console.log(applicaDueVolte(3, doppio))      // 12
console.log(applicaDueVolte(3, piuDieci))    // 23

Una funzione che riceve o restituisce funzioni si chiama funzione di ordine superiore. È il meccanismo su cui si regge la settimana 2.

Es 7

Il registro

sfida

Mettendo insieme tutto: scrivi una funzione schedaStudente(nome, voto) che restituisce una stringa fatta così:

Sara — voto 8 — promosso

Il giudizio finale deve essere "promosso" con voto da 6 in su, "da recuperare" sotto. Se il voto passato non è valido (fuori dall'intervallo 0–10), la funzione deve restituire invece "Sara — voto non valido".

Riusa le funzioni che hai già scritto negli esercizi 2 e 3 invece di riscrivere la logica.

Il tuo codice

Hai due casi da distinguere, quindi ti serve un if o un ternario che sceglie tra due template literal diversi.

Il trattino lungo si ottiene copiandolo da qui: —. Va bene anche un trattino normale.

const votoValido = v => v >= 0 && v <= 10
const esito = v => v >= 6 ? "promosso" : "da recuperare"

const schedaStudente = (nome, voto) =>
  votoValido(voto)
    ? `${nome} — voto ${voto} — ${esito(voto)}`
    : `${nome} — voto non valido`

console.log(schedaStudente("Sara", 8))
console.log(schedaStudente("Luca", 4))
console.log(schedaStudente("Anna", 15))

Ogni funzione fa una cosa sola e le altre la riusano. È il principio che seguirai per tutto l'anno: funzioni piccole che si compongono.

Errori tipici

I messaggi che vedrai più spesso, cosa significano davvero e dove guardare per correggerli.

Otto domande

Quale dichiarazione useresti per una variabile che deve contare i click e quindi cambia nel tempo?

Il valore deve cambiare, quindi serve let. Con const avresti un TypeError alla prima riassegnazione; var funzionerebbe ma non si usa più; assegnare senza dichiarare crea una variabile globale implicita ed è una pessima abitudine.

Che cosa stampa console.log(5 === "5")?

=== confronta valore e tipo: un numero non è mai uguale a una stringa. Con == avresti ottenuto true, perché la stringa viene convertita in numero prima del confronto: è esattamente il motivo per cui == non si usa.

Quale di questi valori è truthy, cioè viene considerato vero in un if?

"0" è una stringa non vuota, quindi è vera. Solo la stringa vuota è falsy. Gli altri tre — 0, "", undefined — sono tutti nella lista dei sei valori falsy.

Con const lista = [1, 2], quale operazione genera un errore?

Solo la riassegnazione dell'intero array è vietata. const protegge il legame tra il nome e il valore, non il contenuto del valore: aggiungere elementi o modificarne uno è permesso.

Come si scrive correttamente una stringa che inserisce il contenuto della variabile nome?

Servono i backtick e la sintassi completa ${...} con il simbolo del dollaro. Con virgolette o apici singoli la stringa viene stampata alla lettera, dollaro e graffe compresi.

Che cosa restituisce const f = (a, b) => { a + b } quando la chiami?

Le graffe aprono un corpo di funzione vero e proprio, quindi il return diventa obbligatorio. Senza, la funzione calcola la somma, la butta via e restituisce undefined. Il return implicito vale solo nella forma senza graffe.

Vuoi passare la funzione saluta alla funzione esegui. Come si scrive?

Senza parentesi passi la funzione; con le parentesi la esegui subito e passi il suo risultato, che spesso è undefined. È la stessa distinzione che in React separa onClick={gestisci} — corretto — da onClick={gestisci()}, che scatta al caricamento della pagina.

Perché controllare un array con if (risultati) è sbagliato?

Un array vuoto [] non è nella lista dei valori falsy, quindi è vero. La condizione entra anche quando non hai trovato niente. La forma corretta è if (risultati.length > 0).
