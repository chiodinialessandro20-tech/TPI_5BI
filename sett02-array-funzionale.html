Da dove riparti

La settimana scorsa hai imparato che una funzione è un valore: si può assegnare a una costante e si può passare a un'altra funzione come argomento. L'esercizio 6 era esattamente quello.

Oggi quel meccanismo diventa lo strumento principale. map, filter, find e reduce sono metodi che ricevono una funzione e la applicano a ogni elemento di un array. Se ti è chiaro che esegui(saluta) non è esegui(saluta()), oggi hai già mezza strada fatta.

Prima console: ripasso e assaggio

Guarda bene la penultima riga: numeri.map(doppio), senza parentesi dopo doppio. Stai passando la funzione, non il suo risultato. Sarà map a chiamarla, una volta per ogni numero.

Imperativo e dichiarativo

Il libro apre il paragrafo 9.2 (p. 269) con questa distinzione. Programmare in modo imperativo significa dire come fare una cosa, passo per passo. Programmare in modo dichiarativo significa dire cosa vuoi ottenere, e lasciare il come al linguaggio.

Imperativo · comeDichiarativo · cosa
parti da un array vuoto, scorri con un indice da 0 a lunghezza, prendi l'elemento, moltiplicalo per 2, mettilo in fondo al nuovo array numeri.map(n => n * 2)

Fanno la stessa cosa. La seconda riga si legge in un secondo e non può contenere un errore di indice, perché di indici non ne ha.

Sezione 01

Oggetti

Un contenitore di coppie nome-valore. Serve a tenere insieme i dati che descrivono una stessa cosa.

L'oggetto letterale

Un array raccoglie elementi dello stesso genere e li identifica con un numero. Un oggetto raccoglie proprietà diverse fra loro e le identifica con un nome.

const utente = {
  nome: "John",
  eta: 30
}

Le graffe scritte così si chiamano oggetto letterale: stai scrivendo direttamente il valore, senza costruttori né classi. La chiave sta a sinistra dei due punti, il valore a destra, e le coppie si separano con la virgola.

Esempio ripreso dai materiali di laboratorio di Paola, index02.js (sezione Index.02 del repository "Pillole di JavaScript"). Il libro dà per acquisita la sintassi degli oggetti.

Leggere e scrivere una proprietà

Due notazioni: il punto e le parentesi quadre.

Le due notazioni
Quale delle due usare

Il punto, quasi sempre: è più corto e più leggibile. Le quadre servono in due casi: quando il nome della proprietà è dentro una variabile, e quando il nome contiene caratteri che il punto non accetta, per esempio uno spazio o un trattino.

Aggiungere e togliere proprietà

Un oggetto JavaScript non ha uno schema fisso. Puoi aggiungere una proprietà che non esisteva, semplicemente assegnandola. E puoi rimuoverla con delete.

Modifica, aggiunta, cancellazione
Ma non era const?

Sì, ed è la stessa cosa vista la settimana scorsa con gli array. const vieta di riassegnare utente a un altro oggetto, non vieta di modificare l'interno dell'oggetto. Prova ad aggiungere utente = {} in fondo alla console qui sopra: quello sì che dà errore.

Una proprietà che non c'è vale undefined

Questa è la caratteristica da ricordare. Se chiedi una proprietà che l'oggetto non ha, JavaScript non ti dà errore: ti restituisce undefined.

Proprietà inesistente
Comodo e insidioso

È comodo perché puoi interrogare qualsiasi proprietà senza controlli. È insidioso perché un errore di battitura non si manifesta: se scrivi utente.nomee ottieni undefined e il programma prosegue, magari stampando "Benvenuto undefined" senza dirti dove hai sbagliato.

Quando un valore inatteso è undefined, il primo sospetto è sempre il nome della proprietà scritto male.

Una funzione dentro un oggetto

Il valore di una proprietà può essere qualsiasi cosa, funzioni comprese. Una funzione dentro un oggetto si chiama metodo. Dentro il metodo, this indica l'oggetto stesso.

Un metodo

L'oggetto auto con il metodo che si autodescrive viene dall'esercizio 1 dell'esercitazione di laboratorio di Paola (esercitazione.md), non dal libro.

Quando chiami auto.descrizione(), this vale auto. Nota le parentesi: senza, otterresti la funzione invece del suo risultato. Provalo togliendo le parentesi nella console qui sopra.

Sezione 02

Array di oggetti

La struttura dati di tutto l'anno: una lista in cui ogni elemento è un oggetto con le stesse proprietà.

Come si scrive

Un array le cui caselle contengono oggetti. Nient'altro che la combinazione delle due cose che già conosci.

const prodotti = [
  { id: 1, nome: "Tastiera", prezzo: 45, disponibile: true },
  { id: 2, nome: "Mouse", prezzo: 25, disponibile: false },
  { id: 3, nome: "Monitor", prezzo: 180, disponibile: true }
]

Questa forma è ovunque: è come arriva una risposta da un'API REST, è come si tiene lo stato di un'applicazione, è come PocketBase ti restituirà i record nella settimana 5. Ogni riquadro che vedrai in una pagina web nasce quasi sempre da un elemento di un array come questo.

Accedere ai dati

Si legge da sinistra a destra: prodotti[0] è un oggetto, e su quell'oggetto puoi mettere il punto per prendere una proprietà.

Il problema: quando la proprietà non c'è

Nel mondo reale i dati sono irregolari. Un record può avere una proprietà che un altro non ha, e un dato che arriva da un server può mancare del tutto.

Attenzione: questo va in errore

La prima riga funziona: chiedi una proprietà che non c'è e ottieni undefined. La seconda no: stai chiedendo la proprietà via di undefined, e undefined non ha proprietà. Il messaggio è TypeError: Cannot read properties of undefined.

Concatenamento opzionale ?.

L'operatore ?. risolve esattamente questo. valore?.prop funziona come valore.prop se valore esiste; se invece è null o undefined, si ferma e restituisce undefined invece di lanciare l'errore.

Tre modi di difendersi, uno solo buono

Il confronto fra le tre soluzioni è ripreso da index03.js dei materiali di laboratorio di Paola (sezione Index.03). Nel libro ?. e ?? non sono trattati.

Coalescenza dei nulli ??

Serve a dare un valore predefinito quando il dato manca. Somiglia a ||, ma c'è una differenza che conta.

  • a || b restituisce b se a è un qualunque valore falsy — quindi anche se a è 0 o ""
  • a ?? b restituisce b solo se a è null o undefined
La differenza in sei righe
Perché la differenza è seria

Immagina const quantita = ordine.quantita || 1. Se l'ordine ha davvero quantità 0, con || diventa 1: hai appena falsificato un dato. Con ?? resta 0, che è la verità.

Vale per ogni numero che può legittimamente valere zero e per ogni stringa che può essere vuota: punteggi, contatori, note, giacenze.

I due operatori insieme

Si usano in coppia: ?. attraversa la catena in sicurezza, ?? mette il valore di riserva se il risultato è mancante.

La forma completa

Esempio adattato dall'esercizio 2 dell'esercitazione di laboratorio di Paola.

Dove ti servirà

Nella settimana 6 leggerai dati che arrivano da un server. Prima che la risposta arrivi, la variabile che li contiene è vuota: dati?.risultati evita che la pagina esploda nel frattempo. È uno degli usi più frequenti di ?. in React.

Sezione 03 · la più importante

map()

Un trasformatore. Prende un array, applica una funzione a ogni elemento, restituisce un nuovo array della stessa lunghezza.

Se oggi impari una cosa sola

Che sia questa. Il libro (§ 9.2, p. 269) chiama map() il trasformatore e ne dà due proprietà: restituisce un nuovo array della stessa lunghezza e lascia intatto l'originale. Sono le due cose da sapere a memoria.

La forma

const nuovoArray = vecchioArray.map(funzione)

La funzione che passi riceve un elemento e restituisce quello che quell'elemento deve diventare. map la chiama una volta per ogni casella e raccoglie i risultati in ordine.

Il primo map

L'array [1, 2, 3, 4, 5, 6] con quadrati, pari e somma è l'esercizio 6 dell'esercitazione di laboratorio di Paola. Lo useremo come filo conduttore in tutte le sezioni.

Sei uno a uno, mai uno a due

Sei numeri entrano, sei quadrati escono. map non può saltare elementi e non può aggiungerne: la lunghezza del risultato è per costruzione uguale a quella di partenza.

PartenzaFunzioneRisultato
[1, 2, 3]n => n * 2[2, 4, 6]
[1, 2, 3]n => n > 1[false, true, true]
["a", "b"]s => s.toUpperCase()["A", "B"]

Il tipo può cambiare — nella seconda riga entrano numeri ed escono booleani — la quantità no.

Se vuoi meno elementi, map non è lo strumento

È l'errore numero uno con questo metodo: usarlo per selezionare. Se il tuo obiettivo è ottenere solo alcuni elementi, ti serve filter(), che vedrai nella sezione 04. map trasforma tutti, sempre.

Immutabilità

map() non tocca l'array di partenza: ne costruisce uno nuovo. È quello che il libro chiama immutabilità (p. 269), e non è un dettaglio.

Due strade, una sola sicura

Nella prima strada il dato di partenza è perso. Se più avanti ti serve il prezzo senza IVA, non ce l'hai più. Nella seconda hai entrambi.

In React è obbligatorio

React capisce che deve ridisegnare l'interfaccia perché confronta il vecchio array con il nuovo. Se modifichi l'array esistente al suo posto, il vecchio e il nuovo sono la stessa cosa, React non vede differenze e la pagina non si aggiorna. È uno dei bug più comuni di chi inizia, e la causa è sempre una mutazione al posto di un map.

map su array di oggetti: la proiezione

Qui map mostra la sua vera utilità. Da una lista di oggetti complessi puoi estrarre solo quello che ti serve. Il libro usa il termine proiezione, preso dall'algebra relazionale e da SQL: nella SELECT nome FROM prodotti stai proiettando la tabella su una sola colonna. È la stessa operazione.

Proiezione su una proprietà

La funzione p => p.prezzo è la forma tipica: un parametro, nessuna graffa, nessun return. Il libro la cita esplicitamente come esempio di arrow function senza return quando la logica è semplice.

Proiettare su un nuovo oggetto

Non sei costretto a restituire una proprietà: puoi restituire un oggetto costruito da te, con solo i campi che ti servono o con campi calcolati.

Da tre campi a due, uno calcolato
Le parentesi tonde attorno alle graffe

Guarda bene: p => ({ ... }), non p => { ... }. Senza le tonde, JavaScript legge le graffe come il corpo della funzione e non come un oggetto, e la funzione restituisce undefined.

Le tonde dicono "questa è un'espressione, non un blocco". Provalo: togli le tonde nella console qui sopra ed esegui.

Da map a stringhe

La funzione può restituire qualsiasi cosa, anche una frase costruita con un template literal. Questo è il passo che porta dritto a React.

Un array di frasi

forEach è il cugino povero di map: scorre l'array ed esegue qualcosa per ogni elemento, ma non restituisce niente. Si usa quando vuoi un effetto (stampare, salvare), non un nuovo array. Se ti serve il risultato, usa map.

Il secondo parametro: l'indice

La funzione passata a map può ricevere un secondo parametro: la posizione dell'elemento, contata da 0.

Elemento e indice

Dove finisce tutto questo: React

Nella settimana 7 disegnerai una lista di prodotti in React. Il codice sarà questo:

<ul>
  {prodotti.map(p => (
    <li key={p.id}>{p.nome} — {p.prezzo} euro</li>
  ))}
</ul>

Confrontalo con la console di due riquadri fa. È identico: prodotti.map(p => ...), con le tonde attorno al valore restituito, e dentro un template al posto della stringa. Cambia solo che il risultato non è testo ma un pezzo di interfaccia.

Quel key

L'attributo key={p.id} serve a React per riconoscere quale riga è quale quando la lista cambia: se ne cancelli una, React deve sapere quale togliere senza ridisegnare tutte le altre. Deve essere un valore unico e stabile, e per questo si usa l'id del record, mai la posizione nell'array.

Non serve che tu lo capisca a fondo adesso. Serve che quando lo vedrai in settimana 7 tu riconosca il map sotto.

Sezione 04

filter() e find()

Il setaccio e il primo riscontro. Si somigliano, restituiscono cose diverse, e confonderli costa ore.

filter(): il setaccio

Il libro (§ 9.2, p. 269) lo chiama setaccio. Scorre l'array, tiene solo gli elementi per cui la funzione restituisce true, e ne costruisce uno nuovo.

La funzione che passi a filter si chiama predicato: deve restituire un booleano, vero o falso. Non trasforma niente, decide soltanto se tenere o scartare.

Il setaccio
MetodoLa funzione restituisceIl metodo restituisce
map()Il nuovo valore dell'elementoUn array della stessa lunghezza
filter()true o falseUn array più corto o uguale
filter su oggetti

L'ultima riga è il caso da tenere a mente: nessun prodotto soddisfa la condizione, e filter restituisce un array vuoto. Non null, non undefined: [].

La trappola dell'array vuoto

Te l'avevo annunciata la settimana scorsa: un array vuoto è truthy. Non è nella lista dei sei valori falsy, quindi in un if è vero.

Il bug e la sua correzione
La regola

Dopo un filter non si scrive mai if (risultati). Si scrive if (risultati.length > 0). Il libro lo segnala esplicitamente a p. 269.

Il bug è cattivo perché la pagina non va in errore: mostra semplicemente "Trovati 0 prodotti" o una lista vuota dove ti aspettavi un messaggio.

find(): il primo riscontro

Stessa firma di filter, un predicato che restituisce vero o falso. Ma find si ferma al primo elemento che soddisfa la condizione e restituisce quell'oggetto, non un array.

find contro filter

Le ultime due righe sono la fonte di metà degli errori su questi metodi. Con filter devi scrivere conFilter[0].nome; con find il punto lo metti direttamente.

Quale usare

Quando cerchi per un identificatore unico — un id, un codice, una matricola — usa find(). È semanticamente corretto: sai già che il risultato è uno solo, e prendere un array da un solo elemento è una complicazione inutile. Il libro lo dice a p. 269.

Quando ti aspetti più risultati, usa filter().

find quando non trova

Restituisce undefined. Quindi prodotti.find(p => p.id === 99).nome lancia TypeError: Cannot read properties of undefined: è la stessa scena della sezione 02.

La difesa la conosci già: prodotti.find(p => p.id === 99)?.nome ?? "non trovato".

find che non trova, e la difesa

Due parenti utili: some() e every()

Stesso schema, ma restituiscono un booleano. some risponde "almeno uno?", every risponde "tutti?".

some ed every

Gli esempi con some() ed every() vengono dall'esercizio 6 dell'esercitazione di laboratorio di Paola (sezione Index.08 del repository). Il libro tratta solo map, filter, find e reduce.

Sezione 05

reduce()

Da un array a un solo valore. È il più potente dei quattro ed è quello che spaventa: ci arriviamo per gradi.

Il problema

Hai un array di numeri e vuoi la somma. Non un array: un numero. Né map né filter sanno farlo, perché entrambi restituiscono array.

Il libro (§ 9.2, p. 269) chiama reduce() il metodo di sintesi e usa l'immagine della palla di neve: un accumulatore che rotola lungo l'array e a ogni elemento cresce.

La forma

array.reduce((accumulatore, elemento) => nuovoAccumulatore, valoreIniziale)

Due cose da passare: una funzione con due parametri e un valore iniziale. La funzione riceve la palla di neve com'è adesso e l'elemento corrente, e restituisce la palla aggiornata.

La somma, passo per passo

Leggi le righe stampate una per una: è tutto il meccanismo. L'accumulatore parte da 0, che è il valore iniziale, e a ogni giro diventa il valore restituito dal giro precedente.

Il valore iniziale va scritto sempre

Il libro insiste su questo punto: l'accumulatore va sempre dichiarato esplicitamente. Tecnicamente puoi ometterlo, e allora reduce usa il primo elemento come accumulatore di partenza. Ma con un array vuoto quel comportamento lancia un TypeError, e con un array di oggetti dà risultati assurdi.

Costa due caratteri: scrivi la virgola e il valore iniziale.

Cosa succede senza valore iniziale

Il valore iniziale decide il tipo del risultato

Se parti da 0, il risultato è un numero. Se parti da "", è una stringa. Se parti da [], è un array. Se parti da {}, è un oggetto.

Quattro reduce, quattro tipi

reduce su array di oggetti

L'uso più frequente nella pratica: totali, medie, conteggi.

Totale di un carrello

Perché il libro lo chiama "il padre di tutti"

Con un accumulatore che parte da [], reduce può simulare sia map sia filter. Non è un modo di scrivere codice: è un modo di capire che i tre metodi sono la stessa idea applicata in modi diversi.

map e filter riscritti con reduce

I tre puntini ... sono l'operatore spread: [...acc, x] costruisce un nuovo array con dentro tutto il contenuto di acc più x. Ancora immutabilità: non modifichi acc, ne fai uno nuovo.

Nella pratica

Nel codice vero scrivi map quando trasformi e filter quando selezioni: si leggono meglio. reduce lo tieni per quando devi arrivare a un valore singolo — un totale, una media, un conteggio, un raggruppamento.

Es 1

L'oggetto auto

base

Crea un oggetto auto con le proprietà marca uguale a "Fiat", modello uguale a "Punto" e anno uguale a 2012.

Aggiungi un metodo descrizione() che restituisce la frase Questa è una Fiat Punto del 2012. costruita con un template literal e con this.

Poi aggiungi la proprietà colore dopo aver creato l'oggetto, ed elimina anno con delete. Stampa l'oggetto dopo ogni modifica.

Il tuo codice

Il metodo si scrive dentro le graffe come una qualsiasi proprietà, ma con la sintassi breve nome() { ... }. Dentro, per leggere le altre proprietà dello stesso oggetto, usa this. seguito dal nome.

Per aggiungere una proprietà dopo, basta assegnarla: auto.colore = .... Per toglierla, delete auto.anno.

const auto = {
  marca: "Fiat",
  modello: "Punto",
  anno: 2012,
  descrizione() {
    return `Questa è una ${this.marca} ${this.modello} del ${this.anno}.`
  }
}

console.log(auto.descrizione())

auto.colore = "rosso"
console.log(auto)

delete auto.anno
console.log(auto)
console.log(auto.anno)   // undefined

Nota l'ultima riga: dopo delete la proprietà non c'è più, ma chiederla non dà errore. Restituisce undefined.

Es 2

Proprietario mancante

base

Partendo dall'oggetto auto dell'esercizio 1, che non ha la proprietà proprietario, stampa il nome del proprietario. Se non c'è, deve comparire Non ci sono dati sul proprietario.

Usa ?. per attraversare la catena e ?? per il valore di riserva. Poi aggiungi davvero il proprietario e riesegui la stessa riga: deve stampare il nome.

Il tuo codice

La catena da attraversare è auto → proprietario → nome. Il punto interrogativo va messo dove la catena può interrompersi, cioè dopo proprietario.

Attenzione a non usare || al posto di ??: qui il risultato sarebbe uguale, ma prendi subito l'abitudine giusta.

const auto = { marca: "Fiat", modello: "Punto", anno: 2012 }

console.log(auto.proprietario?.nome ?? "Non ci sono dati sul proprietario")

auto.proprietario = { nome: "Paola" }

console.log(auto.proprietario?.nome ?? "Non ci sono dati sul proprietario")

const chi = auto.proprietario?.nome ?? "Sconosciuto"
console.log(`Il proprietario è: ${chi}`)

Senza ?. la prima riga darebbe TypeError: Cannot read properties of undefined. Provalo: togli il punto interrogativo ed esegui.

Es 3

Quadrati e pari

base

Dato l'array numeri = [1, 2, 3, 4, 5, 6]:

  • con map() costruisci l'array dei quadrati
  • con filter() costruisci l'array dei soli numeri pari
  • con reduce() calcola la somma di tutti i numeri

Stampa i tre risultati e, alla fine, stampa numeri: deve essere ancora quello di partenza.

Il tuo codice

Tutte e tre le funzioni sono arrow function di una riga, senza graffe e senza return.

Per i pari, il resto della divisione per 2: n % 2 === 0. Per la somma, ricordati il valore iniziale 0 dopo la funzione, separato da una virgola.

const numeri = [1, 2, 3, 4, 5, 6]

const quadrati = numeri.map(n => n * n)
console.log(quadrati)          // [1, 4, 9, 16, 25, 36]

const pari = numeri.filter(n => n % 2 === 0)
console.log(pari)              // [2, 4, 6]

const somma = numeri.reduce((acc, n) => acc + n, 0)
console.log(somma)             // 21

console.log(numeri)            // [1, 2, 3, 4, 5, 6]: intatto

Nessuno dei tre metodi ha toccato numeri. È l'immutabilità di cui parla il libro a p. 269.

Es 4

Il listino

intermedio

Dato l'array di prodotti qui sotto, produci con map():

  • l'array dei soli nomi
  • l'array delle frasi Tastiera costa 45 euro, una per prodotto
  • un nuovo array di oggetti con solo nome e prezzoIvato, dove l'IVA è al 22%
Il tuo codice

I primi due punti sono map normali: la funzione restituisce una proprietà nel primo caso, un template literal nel secondo.

Il terzo è quello con la trappola: se la funzione deve restituire un oggetto letterale, devi racchiuderlo fra parentesi tonde, altrimenti le graffe vengono lette come corpo della funzione.

const prodotti = [
  { id: 1, nome: "Tastiera", prezzo: 45 },
  { id: 2, nome: "Mouse", prezzo: 25 },
  { id: 3, nome: "Monitor", prezzo: 180 }
]

const nomi = prodotti.map(p => p.nome)
console.log(nomi)

const frasi = prodotti.map(p => `${p.nome} costa ${p.prezzo} euro`)
console.log(frasi)

const listino = prodotti.map(p => ({
  nome: p.nome,
  prezzoIvato: p.prezzo * 1.22
}))
console.log(listino)

Il primo map è la proiezione di cui parla il libro: da oggetti complessi tieni una sola colonna, come una SELECT nome in SQL.

Riscaldamento

Quindici minuti per riattivare quello che hai fatto l'altro giorno. Tre micro-attività da cinque minuti l'una: un errore da trovare, un codice da completare, un risultato da prevedere.

Uno · trova l'errore

Questo codice dovrebbe stampare un array di tre oggetti con la sola proprietà nome. Stampa invece tre undefined. Correggilo.

Correggi ed esegui

Guarda le graffe dopo la freccia. JavaScript non sta leggendo un oggetto.

Le graffe vengono interpretate come corpo della funzione, non come oggetto letterale: la funzione non restituisce niente. Servono le parentesi tonde attorno:

const listino = prodotti.map(p => ({ nome: p.nome }))

In alternativa, apri il blocco e scrivi il return:

const listino = prodotti.map(p => {
  return { nome: p.nome }
})

Curiosità utile: con due proprietà lo stesso errore non dà undefined ma un SyntaxError, perché la virgola dentro un blocco di istruzioni non ha senso. Provalo aggiungendo , prezzoIvato: p.prezzo * 1.22 nel riquadro qui sopra.

Due · completa

Completa le tre righe mancanti. La prima deve dare l'array dei nomi, la seconda i soli prodotti sotto i 100 euro, la terza il prodotto con id uguale a 2.

Completa ed esegui

Tre metodi diversi, uno per riga. L'ultima riga della console fa cercato.nome con il punto diretto: questo ti dice che cercato deve essere un oggetto, non un array.

const nomi = prodotti.map(p => p.nome)
const economici = prodotti.filter(p => p.prezzo < 100)
const cercato = prodotti.find(p => p.id === 2)

Se avessi usato filter nell'ultima riga, cercato.nome darebbe undefined: un array non ha la proprietà nome. Avresti dovuto scrivere cercato[0].nome.

Tre · prevedi il risultato

Prima di eseguire, scrivi su un foglio cosa stampa ognuna di queste righe. Poi esegui e confronta.

Prima prevedi, poi esegui
Le risposte, se ne hai sbagliata qualcuna
  • [false, true, true] — map restituisce sempre tre elementi, qui booleani
  • [] — filter senza riscontri restituisce un array vuoto
  • undefined — find senza riscontri restituisce undefined, non []
  • 0 — la lunghezza dell'array vuoto, ed è il modo corretto di verificare "non ho trovato niente"
  • 106 — l'accumulatore parte da 100, non da 0

Es 5

Cercare per id

base

Dato l'array di prodotti, scrivi una funzione cercaPerId(lista, id) che restituisce il nome del prodotto con quell'id.

Se l'id non esiste, la funzione deve restituire "prodotto non trovato" invece di andare in errore. Provala con 2 e con 99.

Il tuo codice

Cerchi per identificatore unico, quindi il metodo giusto è find, non filter.

Per il caso "non trovato" hai già gli strumenti: find restituisce undefined, e ?. con ?? gestiscono esattamente questa situazione.

const cercaPerId = (lista, id) =>
  lista.find(p => p.id === id)?.nome ?? "prodotto non trovato"

console.log(cercaPerId(prodotti, 2))    // Mouse
console.log(cercaPerId(prodotti, 99))   // prodotto non trovato

Si legge da sinistra: cerca l'elemento, se c'è prendi nome, se il risultato manca usa la frase di riserva. Tre operatori in una riga, ognuno con un compito preciso.

Es 6

Statistiche di magazzino

intermedio

Sullo stesso array di prodotti, con giacenza aggiunta, calcola e stampa:

  • il valore totale del magazzino, cioè la somma di prezzo × giacenza
  • il prezzo medio dei prodotti
  • il prodotto più caro

Usa reduce() per tutti e tre.

Il tuo codice

Per il totale, l'accumulatore parte da 0 e a ogni giro cresce del prodotto fra prezzo e giacenza.

Per la media, calcola prima la somma dei prezzi con lo stesso schema, poi dividi per prodotti.length. Non esiste un metodo media().

Per il più caro, l'accumulatore non è un numero ma un oggetto: a ogni giro tieni quello con il prezzo maggiore. Il valore iniziale può essere prodotti[0].

const valore = prodotti.reduce((acc, p) => acc + p.prezzo * p.giacenza, 0)
console.log(`Valore magazzino: ${valore} euro`)

const sommaPrezzi = prodotti.reduce((acc, p) => acc + p.prezzo, 0)
const media = sommaPrezzi / prodotti.length
console.log(`Prezzo medio: ${media} euro`)

const piuCaro = prodotti.reduce(
  (max, p) => p.prezzo > max.prezzo ? p : max,
  prodotti[0]
)
console.log(`Il più caro: ${piuCaro.nome}`)

Il terzo è il salto concettuale: l'accumulatore può essere di qualsiasi tipo, oggetti compresi. Il valore iniziale prodotti[0] non è casuale — partire da {} darebbe undefined al primo confronto.

Es 7

Concatenamento

avanzato

I metodi si concatenano: filter() restituisce un array, e su un array puoi chiamare map(). Si scrive lista.filter(...).map(...).

Dall'array di prodotti, ottieni in una sola espressione l'array dei nomi dei soli prodotti disponibili che costano meno di 100 euro.

Poi prova a invertire l'ordine, scrivendo .map().filter(), e osserva cosa succede.

Il tuo codice

L'ordine conta: prima riduci la lista, poi trasforma quello che resta. Se prima trasformi in nomi, ti restano solo stringhe e il prezzo non c'è più.

Le due condizioni del filtro si uniscono con &&. Per la disponibilità non serve === true: la proprietà è già un booleano.

const risultato = prodotti
  .filter(p => p.disponibile && p.prezzo < 100)
  .map(p => p.nome)

console.log(risultato)   // ["Tastiera", "Webcam"]

Andando a capo prima di ogni punto la catena si legge come un elenco di passaggi: prendi i prodotti, tieni quelli disponibili sotto i 100, estrai i nomi.

Invertendo l'ordine, .map(p => p.nome) produce un array di stringhe e il filter successivo non trova né disponibile né prezzo: entrambe le proprietà valgono undefined, il predicato è sempre falso, il risultato è [].

Regola pratica: filtra prima, trasforma dopo. Fra l'altro è anche più efficiente, perché trasformi meno elementi.

Es 8

Il registro dei voti

sfida

Dato un array di studenti, dove ogni studente ha un nome e un array voti, scrivi una funzione iBravi(lista) che restituisce l'array dei nomi di chi ha una media dei voti superiore a 8.

Ti servono tutti e tre i metodi: reduce per la media di ciascuno, filter per selezionare, map per tenere solo i nomi.

Con i dati dell'esempio il risultato deve essere ["Sara"].

Il tuo codice

Spezza il problema. Scrivi prima una funzione a parte, media(voti), che riceve un array di numeri e restituisce la media: è reduce diviso length. Provala da sola prima di andare avanti.

Poi la catena diventa leggibile: filtra gli studenti la cui media(s.voti) supera 8, e mappa il risultato sui nomi.

Attenzione: qui ci sono due array annidati. studenti è l'array esterno, s.voti è un array dentro ogni elemento.

Versione leggibile, con la media estratta in una funzione a parte:

const media = voti => voti.reduce((acc, v) => acc + v, 0) / voti.length

const iBravi = lista => lista
  .filter(s => media(s.voti) > 8)
  .map(s => s.nome)

console.log(iBravi(studenti))   // ["Sara"]

Versione compatta, tutto in una catena:

const iBravi = lista => lista
  .filter(s => (s.voti.reduce((acc, v) => acc + v, 0) / s.voti.length) > 8)
  .map(s => s.nome)

Funzionano allo stesso modo, ma la prima si legge. Estrarre media in una funzione con un nome è quello che farai sempre nel codice vero: funzioni piccole che si compongono, come nell'esercizio 7 della settimana scorsa.

Gli esercizi 3 e 8 riprendono gli esercizi 6 e 7 dell'esercitazione di laboratorio di Paola. Il libro propone esercizi analoghi sugli stessi metodi: 9.2 conversione prezzi con map, 9.3 filtro delle temperature sopra i 30 gradi, 9.4 voto massimo con reduce (p. 278).

Se hai finito tutto

Per l'ordinamento serve sort(), che non abbiamo visto: cercalo. Attenzione, sort() è l'eccezione fra i metodi di array — modifica l'array originale invece di crearne uno nuovo.

Errori tipici

I messaggi che vedrai più spesso questa settimana, e dove guardare per correggerli.

TypeError: Cannot read properties of undefined (reading 'x') Stai mettendo il punto su qualcosa che non esiste. Le cause tipiche: un find() che non ha trovato niente, una proprietà annidata che manca, un nome scritto male. La difesa è ?..
TypeError: x.map is not a function x non è un array. Spesso è un oggetto singolo, oppure è undefined perché i dati non sono ancora arrivati. Controlla con console.log(x) cosa contiene davvero.
TypeError: Reduce of empty array with no initial value Hai chiamato reduce() su un array vuoto senza valore iniziale. Aggiungi la virgola e il valore iniziale: reduce(fn, 0).

Il ramo "nessun risultato" non viene mai eseguito Stai controllando con if (risultati). Un array vuoto è truthy. Usa if (risultati.length > 0).
L'array originale è cambiato e non doveva Hai usato un ciclo che assegna sulle caselle, oppure sort() o push(). map e filter non modificano mai l'originale; sort e push sì.

Come si indaga

Quando una catena di metodi non dà il risultato atteso, spezzala. Assegna ogni passaggio a una costante e stampala:

const filtrati = prodotti.filter(p => p.prezzo < 100)
console.log(filtrati)                  // è quello che ti aspetti?
const nomi = filtrati.map(p => p.nome)
console.log(nomi)

In due minuti sai qual è il passaggio che sbaglia. Ricomporrai la catena dopo.

Dieci domande

Con const u = { nome: "Pete" }, che cosa stampa console.log(u.eta)?

In JavaScript puoi interrogare qualsiasi proprietà di un oggetto: se non esiste ottieni undefined, senza errore. È comodo, ma nasconde gli errori di battitura nei nomi delle proprietà.

Quanti elementi ha l'array restituito da [1, 2, 3, 4].map(n => n * 2)?

map() è un trasformatore, non un setaccio: applica la funzione a ogni elemento e raccoglie tutti i risultati. La lunghezza del nuovo array è per costruzione uguale a quella dell'originale. Se ti servono meno elementi ti serve filter().

Dopo const nuovi = vecchi.map(n => n * 2), com'è l'array vecchi?

map() costruisce un array nuovo e lascia intatto quello di partenza: è l'immutabilità di cui parla il libro a p. 269. In React è indispensabile, perché il confronto fra vecchio e nuovo array è ciò che fa scattare il ridisegno dell'interfaccia.

Che cosa restituisce prodotti.filter(p => p.prezzo > 10000) se nessun prodotto costa così tanto?

filter() restituisce sempre un array, eventualmente vuoto. E qui scatta la trappola: [] è truthy, quindi if (risultati) è vero anche senza risultati. Si controlla con if (risultati.length > 0).

Devi trovare l'unico studente con matricola 4471. Quale metodo è semanticamente corretto?

Con un identificatore unico si usa find(): si ferma al primo riscontro e restituisce direttamente l'oggetto, così puoi scrivere studente.nome senza passare da [0]. filter() funzionerebbe, ma restituirebbe un array da un solo elemento: una complicazione inutile.

Che cosa restituisce find() quando nessun elemento soddisfa la condizione?

find() restituisce undefined, non un array vuoto: è la differenza con filter(). Perciò mettere subito il punto dopo un find() è rischioso, e la forma sicura è lista.find(...)?.nome ?? "non trovato".

In numeri.reduce((acc, n) => acc + n, 0), a che cosa serve lo 0 finale?

È il valore da cui parte l'accumulatore, la "palla di neve" prima di iniziare a rotolare. Il libro insiste che vada sempre dichiarato esplicitamente: senza, su un array vuoto ottieni TypeError: Reduce of empty array with no initial value. Determina anche il tipo del risultato: 0 per un numero, [] per un array, {} per un oggetto.

Perché const l = p.map(x => { nome: x.nome }) restituisce un array di undefined?

JavaScript legge { ... } dopo la freccia come un blocco di istruzioni, non come un oggetto letterale. Senza return, la funzione restituisce undefined. Si risolve con le tonde — x => ({ nome: x.nome }) — oppure scrivendo il return dentro le graffe.

Che cosa stampa console.log(0 ?? 100)?

?? sostituisce il valore solo se è null o undefined. Lo zero è un dato legittimo e resta. Con || avresti ottenuto 100, falsificando il dato: è il motivo per cui su quantità, punteggi e giacenze si usa ??.

Perché lista.map(p => p.nome).filter(p => p.prezzo < 50) restituisce un array vuoto?

Il map ha già proiettato gli oggetti sui soli nomi: il filter riceve stringhe, per cui p.prezzo vale undefined e il confronto è sempre falso. Concatenare si può eccome, ma l'ordine conta: filtra prima, trasforma dopo. È anche più efficiente, perché trasformi meno elementi.
