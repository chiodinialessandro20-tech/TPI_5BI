Destructuring, spread, immutabilità e moduli

Oggi impari a modificare una lista senza modificarla. Sembra un gioco di parole: è invece la regola su cui poggia tutto React.

Tre formule da memorizzare 7 esercizi Console integrata

Da dove veniamo

La settimana scorsa hai usato map e filter. Hai visto che nessuno dei due tocca l'array di partenza: restituiscono un array nuovo. Quella proprietà ha un nome, ed è il tema di oggi: immutabilità.

Il libro la nomina proprio parlando di map: restituisce un nuovo array della stessa lunghezza e l'originale resta intatto (cap. 9.2, p. 269).

Perché ti serve

Quando arriverai a React, nella settimana 8, i dati della tua applicazione staranno dentro useState. React confronta il vecchio valore e il nuovo per capire se deve ridisegnare la pagina. Il confronto non guarda dentro: guarda se è lo stesso oggetto.

La conseguenza pratica

Se modifichi l'array esistente con push, l'oggetto rimane lo stesso. React confronta, non vede differenze, e non ridisegna niente. Il dato è cambiato ma sullo schermo non succede nulla.

Non è un errore che il browser ti segnala. Non compare nessun messaggio rosso. Semplicemente la pagina resta ferma, e tu passi mezz'ora a cercare un bug che non c'è.

Il traguardo di oggi

A fine giornata sai eseguire le tre manipolazioni immutabili. Sono queste, e sono il 90% del codice che scriverai in React:

// aggiungere
[...lista, nuovo]

// rimuovere
lista.filter(x => x.id !== id)

// modificare
lista.map(x => x.id === id ? {...x, fatto: true} : x)

Non devi capirle adesso. Devi arrivarci alla sezione 05 con gli strumenti giusti in mano: il ... lo vedi nella sezione 03, il perché nella 04.

Provala subito

Ecco la differenza in cinque righe. Esegui e guarda i due output.

Mutabile contro immutabile

Nel primo caso l'originale è cambiato senza che tu l'abbia chiesto. Nel secondo è rimasto intatto e hai un array nuovo accanto. È tutta qui la differenza.

Che cosa sai fare a fine giornata

  • Estrarre valori da array e oggetti con il destructuring
  • Usare ... per copiare, concatenare e unire
  • Spiegare perché const non blocca il contenuto di un array
  • Riconoscere il limite dello shallow copy e sapere quando ti farà male
  • Scrivere a memoria le tre manipolazioni immutabili
  • Dividere il codice in moduli con import ed export
Sezione 01

Destructuring di array

Un modo compatto per estrarre più valori da un array in un colpo solo. Meno righe, più leggibile.

Destructuring e spread non sono trattati esplicitamente dal libro adottato. Il capitolo 9 li usa nel codice ma non li spiega. Questa sezione e le tre successive vengono dai materiali di laboratorio (index06.js e index07.js), non dal manuale: non cercarli sull'indice del testo.

La versione classica

Per prendere i primi elementi di un array scrivi una riga per ciascuno:

const array = [1, 2, 3, 4, 5]
const a = array[0]
const b = array[1]
const c = array[2]

La versione con destructuring

Metti a sinistra le parentesi quadre con i nomi che vuoi. JavaScript assegna per posizione.

const array = [1, 2, 3, 4, 5]
const [a, b, c] = array
console.log(a, b, c)   // 1 2 3
Come si legge

Le parentesi quadre a sinistra dell'uguale non creano un array. Sono uno schema: dicono "il valore a destra è un array, prendi il primo elemento e chiamalo a, il secondo e chiamalo b".

Le quattro forme

Il parametro rest

I tre puntini nella terza forma si chiamano rest: raccolgono tutto quello che avanza dentro un nuovo array. Attenzione, deve stare per forza in ultima posizione: [...resto, n] è un errore di sintassi.

Stessi tre puntini, due significati opposti

Nella sezione 03 vedrai gli stessi ... usati per espandere un array. Qui invece raccolgono. Come distinguerli: a sinistra dell'uguale raccolgono (rest), a destra espandono (spread).

Valori di default

Se l'array è più corto dello schema, gli elementi mancanti valgono undefined. Puoi dare un valore di riserva con l'uguale:

Quando manca un valore

Il default scatta solo quando il valore è undefined. Se l'array contiene null o 0, il default non scatta: quei valori esistono.

Scambio di valori

Un uso classico. Senza destructuring servirebbe una variabile temporanea; qui basta una riga.

Scambio in una riga
Il punto e virgola davanti

Nota il ; prima della parentesi quadra. Serve perché la riga inizia con [: senza, JavaScript prova a leggerla come continuazione della riga precedente e sbaglia. Se dichiari le variabili con let e le scambi su righe separate, mettilo sempre.

Con le funzioni

Una funzione JavaScript restituisce un solo valore. Restituendo un array e destrutturandolo in ingresso ottieni l'effetto di più valori di ritorno:

function dividi(a, b) {
  return [Math.floor(a / b), a % b]
}

const [quoziente, resto] = dividi(17, 5)
console.log(quoziente, resto)   // 3 2
Sezione 02

Destructuring di oggetti

Uguale a quello degli array, ma i valori si prendono per nome, non per posizione. È la forma che userai di più.

Da così a così

La versione classica ripete il nome dell'oggetto a ogni riga:

const obj = { nome: "Mario", cognome: "Rossi", eta: 30 }
const nome = obj.nome
const cognome = obj.cognome
const eta = obj.eta

La versione con destructuring usa le graffe:

const { nome, cognome, eta } = obj
Il nome deve coincidere

Negli array conta la posizione, negli oggetti conta il nome. const { nome } = obj funziona solo se la proprietà si chiama esattamente nome. Se sbagli una lettera non ottieni un errore: ottieni undefined, che è peggio perché scopri il problema più tardi.

Prova a sbagliare un nome

L'ordine non conta

Siccome si va per nome, puoi scrivere le proprietà nell'ordine che vuoi e puoi prenderne solo alcune:

Ordine libero, selezione libera

L'estrazione di nome ed eta da un oggetto studente riprende l'esercizio 4 dell'esercitazione di laboratorio, non il libro.

Valori di default

Come per gli array, l'uguale dà un valore di riserva quando la proprietà non c'è.

Proprietà mancante

L'ultima riga mostra anche come rinominare: professione: prof2 significa "prendi la proprietà professione e chiamala prof2". Serve quando il nome che arriva dai dati fa a pugni con una variabile che hai già.

Dove lo userai davvero: i parametri

Questa è la parte da ricordare. Il destructuring funziona anche nella lista dei parametri di una funzione. Invece di ricevere un oggetto e poi frugarci dentro, lo apri direttamente all'ingresso.

Destructuring nei parametri
Anticipazione: settimana 7

In React ogni componente è una funzione che riceve un oggetto di dati. Nella pratica non lo si riceve mai intero: si destruttura nei parametri, esattamente come schedaB.

function Card({ titolo, autore }) {
  return <h2>{titolo}</h2>
}

Quelle graffe attorno a titolo nei parametri sono questa cosa, non una novità di React. Se le riconosci adesso, tra quattro settimane leggerai il codice React senza inciampare.

Sezione 03

Spread ...

Tre puntini che aprono un array o un oggetto e ne versano il contenuto dentro un altro. Con questo costruisci le tre formule della sezione 05.

Anche questa sezione viene dai materiali di laboratorio (index07.js, scheda Index.07 del readme). Il libro usa lo spread negli esempi del capitolo 9 ma non lo introduce mai come argomento.

Concatenare due array

...arrayA significa "qui dentro metti gli elementi di arrayA, uno per uno".

Concatenazione

Guarda bene i due output. Nel primo hai sei numeri, nel secondo due array annidati. I puntini sono la differenza tra versare il contenuto e appoggiare il contenitore.

Aggiungere elementi

Puoi mescolare elementi sparsi e array espansi, in qualunque posizione:

In coda, in testa, in mezzo

L'ultima riga è quella che conta: frutti non è cambiato. Lo spread legge e basta.

Clonare

Uno spread da solo, senza aggiunte, produce una copia:

const copia = [...originale]      // array
const copiaObj = { ...oggetto }   // oggetto

Unire oggetti: vince l'ultimo

Con gli oggetti lo spread copia le proprietà. Se la stessa proprietà compare due volte, rimane il valore di destra: l'ultimo scritto sovrascrive i precedenti.

Sovrascrittura
Questa riga vale oro

{ ...utente, attivo: true } significa: nuovo oggetto identico a utente, tranne attivo che vale true. È la terza delle tre manipolazioni immutabili, già quasi completa. La ritrovi nella sezione 05.

La proprietà che vuoi cambiare va scritta dopo lo spread. Se la scrivi prima, lo spread la sovrascrive di nuovo con il valore vecchio e il tuo cambiamento sparisce senza errori.

Espandere gli argomenti di una funzione

Lo spread funziona anche su una chiamata: apre l'array e passa gli elementi come argomenti separati.

Da array ad argomenti

Sezione 04

Valori, riferimenti e shallow copy

Qui si chiude il conto lasciato aperto nella settimana 1: perché const non blocca il contenuto di un array. E si apre il problema più insidioso dello spread.

Due modi di conservare un dato

JavaScript tratta i dati in due modi diversi a seconda del tipo.

TipoCome viene conservato
number, string, boolean, null, undefinedPer valore: la variabile contiene il dato
array, oggetti, funzioniPer riferimento: la variabile contiene un indirizzo che punta al dato

Immagina un armadietto. Con i numeri, il numero è dentro l'armadietto. Con gli array, nell'armadietto c'è un foglietto con scritto dove sta l'array.

Copia per valore

a è rimasto 10: la copia era una copia vera. Ora la stessa cosa con un array.

Copia per riferimento

Non ci sono due array. Ce n'è uno solo con due nomi. lista1 === lista2 dà true perché il confronto tra oggetti guarda l'indirizzo, non il contenuto.

Ecco perché const non basta

Nella settimana 1 avevi visto che const colori = [...] permette comunque colori.push("blu"). Adesso hai la spiegazione: const blocca il foglietto dentro l'armadietto, cioè l'indirizzo. Non blocca l'array che sta all'indirizzo.

Riassegnare significa cambiare foglietto ed è vietato. Modificare il contenuto è permesso, perché il foglietto resta identico.

Confrontare due array

Conseguenza diretta, e sorprendente la prima volta:

Prevedi il risultato

I primi due danno false: stesso contenuto, indirizzi diversi. È proprio su questo confronto che React decide se ridisegnare, ed è per questo che devi produrre un array nuovo a ogni modifica.

Lo shallow copy dello spread

Adesso il punto delicato. Lo spread crea sì un array nuovo, ma copia solo il primo livello. Se dentro ci sono altri array o oggetti, quelli non vengono duplicati: ne vengono copiati gli indirizzi.

Si chiama copia superficiale, o shallow copy.

Primo livello: tutto bene

Qui funziona: due array separati, l'originale intatto. Ora la stessa identica operazione, ma con un array annidato dentro.

Secondo livello: il problema
Sono cambiati tutti e due

Hai modificato solo copiedArray, ma l'output mostra il 99 in entrambi. Il motivo: lo spread ha copiato due caselle, e nella prima c'era l'indirizzo dell'array interno. Quell'array interno è rimasto uno solo, condiviso.

Questo è un bug vero, di quelli che in React ti fanno perdere un pomeriggio. Il dato cambia dove non te lo aspetti e nessun messaggio di errore te lo segnala.

L'esempio dell'array annidato è preso alla lettera da index07.js dei materiali di laboratorio, sezione "L'operatore spread e lo shallow copy". Il libro non affronta questo problema.

Come ci si difende

Tre regole, in ordine di importanza.

  1. Tieni i dati piatti. Un array di oggetti semplici, senza array dentro oggetti dentro array. Il 90% dei problemi non nasce proprio.
  2. Se devi modificare un livello interno, spread anche lì. Uno per ogni livello che tocchi.
  3. Per una copia profonda vera esiste structuredClone(oggetto), disponibile nei browser recenti. Copia tutto a ogni livello. Costa di più: usalo solo se serve davvero.

Sezione 05 · il cuore della settimana

Le tre manipolazioni immutabili

Aggiungere, rimuovere, modificare. Tre formule. Imparale a memoria: sono il 90% del codice che scriverai in React.

Che cosa si intende per immutabile

Non significa che i dati non cambiano mai. Significa che non modifichi il dato esistente: ne produci uno nuovo e sostituisci il vecchio. Il vecchio non lo tocca nessuno.

La lista di partenza

Tutti gli esempi lavorano su questo array di task. È la struttura tipica: un array di oggetti, ognuno con un id univoco.

const task = [
  { id: 1, testo: "Studiare", fatto: false },
  { id: 2, testo: "Allenarsi", fatto: false },
  { id: 3, testo: "Leggere",   fatto: true  }
]

Uno · aggiungere

[...lista, nuovo]

Nuovo array: prima tutti gli elementi vecchi, poi quello nuovo in coda.

Aggiungere: giusto contro sbagliato
Perché push è sbagliato in React

lista.push(nuovo) funziona: l'elemento entra davvero. Ma l'array resta lo stesso oggetto, quindi vecchio === nuovo dà true. React confronta, non vede differenze e non ridisegna. Dato aggiornato, schermo fermo.

Stessa storia per splice, sort, reverse, pop: modificano l'array esistente. Evitali tutti.

Due · rimuovere

lista.filter(x => x.id !== id)

Nuovo array con tutti gli elementi tranne quello con l'id indicato. Leggilo così: "tieni tutti quelli il cui id è diverso da quello che voglio togliere".

Rimuovere: giusto contro sbagliato
Attenzione al verso del confronto

Si scrive !==, non ===. Con === ottieni l'effetto opposto: tieni solo l'elemento che volevi togliere. È lo scambio più frequente. Se la lista si svuota quasi tutta, hai sbagliato il verso.

Tre · modificare

lista.map(x => x.id === id ? {...x, fatto: true} : x)

La più densa delle tre. Si legge in tre pezzi:

  • lista.map(x => ...) — scorri tutti gli elementi e ne produci uno nuovo per ciascuno
  • x.id === id ? A : B — se è l'elemento che cerchi restituisci A, altrimenti restituisci x com'è
  • {...x, fatto: true} — A è una copia dell'oggetto con la sola proprietà fatto cambiata

Nota il ramo : x alla fine. Gli elementi che non ti interessano vanno restituiti tali e quali. Se lo dimentichi, map mette undefined al loro posto e la lista si riempie di buchi.

Modificare: giusto contro sbagliato
Il doppio livello

Modificare vuol dire produrre due cose nuove: un array nuovo (lo fa map) e un oggetto nuovo per l'elemento che cambia (lo fa {...x, ...}).

Se scrivi task.map(t => { if (t.id === 2) t.fatto = true; return t }) ottieni sì un array nuovo, ma gli oggetti dentro sono gli stessi di prima e uno l'hai modificato. Metà lavoro fatto, bug garantito.

Le tre formule insieme

VoglioFormula immutabileDa non usare
Aggiungere [...lista, nuovo] lista.push(nuovo)
Rimuovere lista.filter(x => x.id !== id) lista.splice(i, 1)
Modificare lista.map(x => x.id === id ? {...x, fatto: true} : x) lista[i].fatto = true
Anticipazione: settimana 8

In React lo stato si aggiorna con una funzione, per esempio setTask(...). Quello che ci metti dentro sono esattamente queste tre righe:

setTask([...task, nuovo])
setTask(task.filter(t => t.id !== id))
setTask(task.map(t => t.id === id ? { ...t, fatto: !t.fatto } : t))

Non c'è niente in più da imparare. Cambia solo il setTask( attorno. Se oggi le scrivi senza guardare, la settimana 8 la affronti già mezza fatta.

Es 1

Destructuring di array

base

Parti dall'array [10, 20, 30, 40, 50].

  • Estrai il primo e il terzo elemento saltando gli altri, e stampali
  • Estrai il primo elemento e metti tutto il resto in una variabile coda
  • Estrai sei elementi: il sesto deve valere 0 se manca
Il tuo codice

Per saltare una posizione lascia il posto vuoto tra due virgole. Per raccogliere il resto usa i tre puntini, e ricorda che vanno per forza in ultima posizione.

Il valore di riserva si scrive con l'uguale dentro le parentesi quadre.

const numeri = [10, 20, 30, 40, 50]

// 1. la virgola vuota consuma la posizione di 20
const [primo, , terzo] = numeri
console.log(primo, terzo)          // 10 30

// 2. rest: raccoglie tutto quello che avanza
const [testa, ...coda] = numeri
console.log(testa, coda)           // 10 [20, 30, 40, 50]

// 3. il sesto non esiste, quindi scatta il default
const [a, b, c, d, e, f = 0] = numeri
console.log(f)                     // 0
Es 2

Scheda studente

base

Dato l'oggetto { nome: "Mario", cognome: "Rossi", eta: 18 }, scrivi una funzione scheda che riceve l'oggetto e restituisce la stringa Mario Rossi, 18 anni.

Usa il destructuring nei parametri della funzione. Aggiungi un valore di default: se manca eta, scrivi età non nota al posto del numero.

Il tuo codice

Le graffe vanno dentro le parentesi tonde dei parametri: function scheda({ nome, cognome }).

Per il default, l'uguale si scrive dentro le graffe accanto al nome della proprietà. Poi ti serve un template literal per comporre la frase.

// il destructuring sta nei parametri: la funzione
// riceve l'oggetto intero ma lavora sui singoli campi
const scheda = ({ nome, cognome, eta = "età non nota" }) =>
  `${nome} ${cognome}, ${eta}${typeof eta === "number" ? " anni" : ""}`

console.log(scheda(studente))   // Mario Rossi, 18 anni
console.log(scheda(anonimo))    // Anna Bianchi, età non nota

Va bene anche una versione più semplice con due funzioni separate. Il punto dell'esercizio sono le graffe nei parametri: è la forma che userai in ogni componente React.

Es 3

Spread su array

base

Dato frutti = ["mela", "banana", "arancia"]:

  • Crea altriFrutti con gli stessi elementi più "pera" in fondo
  • Crea conKiwi con "kiwi" davanti a tutti
  • Stampa frutti alla fine e verifica che non sia cambiato
Il tuo codice

La posizione dei tre puntini dentro le quadre decide dove finiscono gli elementi vecchi. Quello che scrivi prima dei puntini va prima, quello che scrivi dopo va dopo.

const frutti = ["mela", "banana", "arancia"]

const altriFrutti = [...frutti, "pera"]
const conKiwi = ["kiwi", ...frutti]

console.log(altriFrutti)   // mela, banana, arancia, pera
console.log(conKiwi)       // kiwi, mela, banana, arancia
console.log(frutti)        // mela, banana, arancia — intatto

Nessuna delle due operazioni ha toccato frutti. Con frutti.push("pera") l'originale sarebbe cambiato.

Es 4

Aggiornare un oggetto senza toccarlo

intermedio

Dato const utente = { nome: "Anna", ruolo: "studente", attivo: false }, scrivi una funzione attiva(u) che restituisce un nuovo oggetto identico ma con attivo: true.

Verifica poi due cose: che l'originale sia ancora attivo: false, e che utente === attiva(utente) dia false.

Il tuo codice

Ti serve lo spread su oggetto seguito dalla proprietà da cambiare. L'ordine conta: la proprietà nuova va scritta dopo i puntini, altrimenti vince il valore vecchio.

Ricorda che una arrow function che restituisce un oggetto letterale ha bisogno delle parentesi tonde attorno alle graffe.

const utente = { nome: "Anna", ruolo: "studente", attivo: false }

// le tonde attorno alle graffe dicono "questo e' un oggetto
// da restituire", non un corpo di funzione
const attiva = u => ({ ...u, attivo: true })

const attivato = attiva(utente)

console.log(attivato)              // attivo: true
console.log(utente)                // attivo: false, intatto
console.log(utente === attivato)   // false: oggetti diversi

Senza le parentesi tonde, u => { ...u } viene letto come corpo di funzione e ottieni un errore di sintassi. È un inciampo classico.

Prima prevedi, poi esegui

Una sola riga crea un array nuovo. Le altre assegnazioni copiano un indirizzo. Chiediti: quanti array esistono davvero in memoria?

Gli array in memoria sono due: quello di partenza e la copia fatta con lo spread.

console.log(a)        // [1, 2, 3] — b e a sono lo stesso array
console.log(c)        // [1, 2]    — copia fatta prima del push
console.log(a === b)  // true      — stesso indirizzo
console.log(a === c)  // false     — array diverso

Due · trova l'errore

Questo codice dovrebbe mettere fatto: true sul task con id 2 senza toccare l'originale. Fa il primo lavoro e sbaglia il secondo. Correggilo.

Correggi ed esegui

map crea un array nuovo, ma gli oggetti dentro sono ancora gli stessi. Quel t.fatto = true scrive dentro l'oggetto originale.

Ti serve un oggetto nuovo per l'elemento che cambi, e l'elemento originale per tutti gli altri.

const aggiornati = task.map(t =>
  t.id === 2 ? { ...t, fatto: true } : t
)

console.log("originale:", task)        // fatto: false, intatto
console.log("aggiornati:", aggiornati) // fatto: true sul secondo

La differenza è tutta in { ...t, fatto: true }: produce un oggetto nuovo invece di scrivere in quello vecchio.

Officina · esercizi 5–7

Es 5

Unire due configurazioni

intermedio

Hai due oggetti: le impostazioni predefinite e quelle scelte dall'utente.

const predefinite = { tema: "chiaro", lingua: "it", notifiche: true }
const utente = { tema: "scuro" }

Costruisci finali in modo che le scelte dell'utente vincano su quelle predefinite, e che le impostazioni non specificate dall'utente restino quelle di default.

Poi prova a invertire l'ordine dello spread e guarda cosa cambia.

Il tuo codice

Sulle proprietà in comune vince quella scritta più a destra. Decidi tu chi deve vincere e mettilo per ultimo.

const finali = { ...predefinite, ...utente }
console.log(finali)
// { tema: "scuro", lingua: "it", notifiche: true }

// invertendo l'ordine, il default sovrascrive la scelta
const sbagliate = { ...utente, ...predefinite }
console.log(sbagliate)
// { tema: "chiaro", lingua: "it", notifiche: true }

Nella versione sbagliata la scelta dell'utente sparisce senza nessun errore. È lo schema con cui ogni libreria gestisce le opzioni: prima i default, poi quello che arriva da fuori.

Es 6

La copia che non copia

avanzato

Dato const squadre = [["Anna", "Luca"], ["Sara", "Marco"]], aggiungi "Gino" alla prima squadra senza modificare squadre.

Prima prova con un solo spread e verifica che non basta. Poi scrivi la versione corretta.

Il tuo codice

Lo spread copia solo il primo livello. Se stai modificando un array che sta dentro, devi creare un array nuovo anche per quello.

Un modo pulito: usa map sull'array esterno e produci un array nuovo per la squadra che cambia.

const squadre = [["Anna", "Luca"], ["Sara", "Marco"]]

// TENTATIVO 1 — non funziona
const copia = [...squadre]
copia[0].push("Gino")
console.log(squadre[0])   // ["Anna","Luca","Gino"] — rovinato!

// TENTATIVO 2 — spread anche sul livello interno
const originali = [["Anna", "Luca"], ["Sara", "Marco"]]
const nuove = originali.map((sq, i) =>
  i === 0 ? [...sq, "Gino"] : sq
)
console.log(nuove[0])       // ["Anna","Luca","Gino"]
console.log(originali[0])   // ["Anna","Luca"] — intatto

È lo stesso schema della terza formula: map per l'array esterno, spread per l'elemento che cambia, l'elemento originale per tutti gli altri.

Es 7

Il gestore di task

sfida

Scrivi tre funzioni che lavorano su un array di task. Nessuna delle tre deve modificare l'array che riceve: tutte restituiscono un array nuovo.

  • aggiungi(lista, testo) — aggiunge un task con fatto: false e un id che non collide con quelli esistenti
  • rimuovi(lista, id) — toglie il task con quell'id
  • completa(lista, id) — inverte fatto sul task con quell'id

Provale in sequenza, partendo dalla lista iniziale, e alla fine stampa la lista originale per dimostrare che non è mai cambiata.

Il tuo codice

Una formula per funzione, nell'ordine in cui le hai imparate: spread, filter, map con ternario.

Per l'id nuovo puoi usare la lunghezza della lista, ma è fragile: se hai rimosso un elemento rischi di riusare un id. Meglio calcolare il massimo degli id esistenti e aggiungere 1. Attenzione alla lista vuota.

Per invertire un booleano c'è il punto esclamativo: !t.fatto.

const iniziale = [
  { id: 1, testo: "Studiare", fatto: false },
  { id: 2, testo: "Allenarsi", fatto: false }
]

// 1. AGGIUNGERE: spread piu' elemento nuovo in coda
const aggiungi = (lista, testo) => {
  const ids = lista.map(t => t.id)
  // lista vuota: parto da 0, altrimenti il massimo esistente
  const nuovoId = ids.length > 0 ? Math.max(...ids) + 1 : 1
  return [...lista, { id: nuovoId, testo: testo, fatto: false }]
}

// 2. RIMUOVERE: filter con il confronto diverso
const rimuovi = (lista, id) => lista.filter(t => t.id !== id)

// 3. MODIFICARE: map, ternario, spread sull'elemento giusto
const completa = (lista, id) =>
  lista.map(t => t.id === id ? { ...t, fatto: !t.fatto } : t)

// prova in sequenza: ogni passo parte dal risultato del precedente
const p1 = aggiungi(iniziale, "Leggere")
const p2 = completa(p1, 2)
const p3 = rimuovi(p2, 1)

console.log("dopo aggiungi:", p1.map(t => t.testo))
console.log("dopo completa:", p2.map(t => t.testo + ":" + t.fatto))
console.log("dopo rimuovi:", p3.map(t => t.testo))
console.log("originale:", iniziale.map(t => t.testo + ":" + t.fatto))

Nota Math.max(...ids): lo spread che espande un array in argomenti separati, dalla sezione 03. E nota che iniziale alla fine è identico all'inizio, pur avendo fatto tre operazioni.

Queste tre funzioni sono, riga per riga, quello che scriverai dentro setTask(...) nella settimana 8.

Se hai finito tutto

Estendi l'esercizio 7 con una quarta funzione rimuoviCompletati(lista) che toglie in un colpo solo tutti i task con fatto: true. È sempre filter, con un predicato diverso.

Poi prova ordina(lista), che restituisce la lista ordinata per testo senza modificare l'originale. Attenzione: sort modifica l'array su cui lo chiami. Ti serve una copia prima.

Sezione 09

Moduli import / export

Come si divide il codice in più file, e perché tutto quello che non dichiari pubblico resta chiuso dentro il suo file.

Questa sezione non si prova qui

I moduli funzionano solo tra file veri, caricati dal browser come moduli ES. La console di questa pagina esegue una stringa di codice isolata: non ha file attorno a sé, quindi import ed export danno errore di sintassi.

Per questo qui trovi solo blocchi di codice da leggere, senza pulsante Esegui. Li proverai per davvero quando creerai il progetto Vite: da quel momento in poi li userai in ogni file.

Il problema

Un'applicazione seria non sta in un file solo. Serve dividerla: un file per l'accesso ai dati, uno per il disegno dell'interfaccia, uno che coordina. Il libro lo chiama refactoring modulare e lo applica a un progetto reale nella sezione 9.6.

Ma se dividi in file, serve un modo perché un file usi le funzioni di un altro. Quel modo sono i moduli ES6 (cap. 9.1, p. 268).

Le due parole

ParolaChe cosa fa
exportRende una cosa disponibile all'esterno del file
importPreleva da un altro file una cosa che è stata esportata

Export con nome

La forma più comune. Metti export davanti a ciò che vuoi rendere pubblico.

// file: utils.js

export const IVA = 22

export const conIva = prezzo => prezzo * (1 + IVA / 100)

// questa non ha export: resta privata a utils.js
const arrotonda = n => Math.round(n * 100) / 100

E dall'altra parte:

// file: main.js

import { conIva, IVA } from "./utils.js"

console.log(IVA)            // 22
console.log(conIva(100))    // 122

console.log(arrotonda(1.5)) // ReferenceError: non esiste qui
Le graffe non sono destructuring

Le graffe di import { conIva } assomigliano al destructuring di oggetti della sezione 02, ma sono un'altra cosa: fanno parte della sintassi dei moduli. L'effetto pratico è simile — scegli per nome cosa prendere — quindi la somiglianza aiuta a ricordarla.

Il percorso vuole l'estensione e il ./ davanti: "./utils.js", non "utils".

Perché una variabile senza export resta privata

Il libro insiste su questo punto (p. 268). Non è una limitazione, è una scelta di progetto.

  • Niente conflitti di nomi. Ogni file ha il suo spazio. Puoi avere una funzione formatta in tre file diversi senza che si pestino i piedi. Prima dei moduli, tutto finiva in un unico spazio globale e i conflitti erano all'ordine del giorno.
  • Least privilege. Esponi solo il minimo necessario. Chi usa il tuo modulo vede l'interfaccia pubblica, non gli ingranaggi. Se domani cambi come funziona arrotonda, nessun altro file si rompe: nessuno poteva usarla.
Least privilege

È lo stesso principio che hai incontrato in sicurezza: dai a ogni parte del sistema solo i permessi che le servono, non uno di più. Qui la "parte del sistema" è un file, e il permesso è la visibilità di una funzione.

Export default

Un file può esportare una cosa principale senza nome vincolante. In import la scegli tu, e non servono le graffe.

// file: Card.js
export default function Card({ titolo }) {
  return "..."
}

// file: main.js
import Card from "./Card.js"          // nome libero, niente graffe
import PocketBase from "pocketbase"   // libreria: senza ./ e senza .js

L'ultima riga viene dal libro (cap. 9.5): quando importi una libreria installata con npm scrivi solo il nome, senza percorso e senza estensione. Il bundler sa dove trovarla dentro node_modules.

Le due forme a confronto

Export con nomeExport default
Quanti per fileQuanti vuoiAl massimo uno
Si scriveexport const f = ...export default f
Si importaimport { f } from "./m.js"import f from "./m.js"
Il nomeDeve coincidereLo scegli tu

Come si divide un progetto

Il libro propone questa suddivisione per l'applicazione del capitolo 9 (sezione 9.6), applicando il principio di singola responsabilità: ogni file fa una cosa sola.

FileResponsabilità
src/api.jsAccesso ai dati: connessione e operazioni di lettura e scrittura
src/map.jsLa mappa
src/ui.jsDOM e template: tutto ciò che si vede
main.jsIl direttore d'orchestra: importa gli altri e li coordina
Il file HTML deve saperlo

Perché il browser tratti un file come modulo serve l'attributo type="module" sul tag script:

<script type="module" src="/main.js"></script>

Senza, import dà errore. Con Vite lo trovi già scritto nel progetto appena creato, quindi non è qualcosa che dovrai ricordarti ogni volta.

Se una casella è rimasta vuota

Torna alla sezione corrispondente e rifai gli esempi nel riquadro di esecuzione. La settima voce è quella che non puoi lasciare in bianco: senza le tre formule, la settimana 8 diventa impraticabile.

Dieci domande

Che cosa vale c dopo const [a, , c] = [10, 20, 30, 40]?

La virgola vuota consuma la seconda posizione senza assegnarla a nessuna variabile. Quindi a prende 10, la posizione di 20 viene saltata e c prende 30. Il 40 avanza e viene ignorato.

Dato const obj = { nome: "Anna" }, che cosa stampa const { cognome } = obj; console.log(cognome)?

Il destructuring di oggetti va per nome: se la proprietà non esiste, la variabile viene creata comunque e vale undefined. Non ottieni nessun errore, ed è proprio questo che rende insidioso sbagliare una lettera nel nome.

Che cosa contiene { ...{ a: 1, b: 2 }, ...{ b: 99 } }?

Sulle proprietà in comune vince l'ultima scritta, cioè quella più a destra. Un oggetto non può avere due volte la stessa chiave, quindi b finisce a 99. È lo schema con cui si sovrascrive un valore predefinito.

Perché const lista = [1, 2]; lista.push(3) non genera errore?

La variabile contiene un indirizzo, non l'array. const vieta di cambiare quell'indirizzo, cioè di scrivere lista = [...]. Il contenuto all'indirizzo resta modificabile. E no, push non restituisce un array nuovo: restituisce la nuova lunghezza.

Dopo const b = [...a] con a = [[1, 2], 3], che effetto ha b[0].push(9)?

Lo spread è una copia superficiale: duplica solo il primo livello. Nella prima casella di b è finito l'indirizzo dello stesso array interno che sta in a. Modificandolo da una parte lo vedi cambiato anche dall'altra. Per copiare tutti i livelli serve uno spread per livello o structuredClone.

Come rimuovi in modo immutabile l'elemento con id === 5 da lista?

filter tiene gli elementi per cui il predicato è vero, quindi serve il confronto diverso. Con === terresti solo l'elemento da togliere. splice modifica l'array esistente. map non elimina niente: restituirebbe un array di true e false lungo uguale.

In lista.map(x => x.id === id ? {...x, fatto: true} : x), a cosa serve la x dopo i due punti?

map costruisce il nuovo array con ciò che la funzione restituisce a ogni giro. Per gli elementi che non ti interessano devi restituire l'elemento stesso, altrimenti al loro posto finisce undefined e la lista si riempie di buchi. E no, map non si interrompe mai: scorre sempre tutto.

Perché in React lista.push(nuovo) spesso non aggiorna la schermata?

L'elemento entra davvero nell'array, e non c'è nessun errore. Ma React confronta il vecchio valore con il nuovo guardando l'identità dell'oggetto, non il contenuto: vecchio === nuovo dà true e il ridisegno non parte. Serve un array nuovo, cioè [...lista, nuovo].

In un modulo ES6, cosa succede a una funzione dichiarata senza export?

Ogni modulo ha il suo spazio dei nomi: fuori esce solo ciò che dichiari con export (cap. 9.1, p. 268). Il vantaggio è doppio: nessun conflitto tra nomi uguali in file diversi, e applicazione del principio di least privilege, cioè esporre il minimo necessario.

Qual è la sintassi corretta per importare la funzione conIva esportata con nome da utils.js?

Gli export con nome si importano fra graffe e con il nome esatto. Senza graffe importeresti l'export default, che qui non c'è. Il percorso di un file tuo vuole il ./ e l'estensione: la forma senza percorso è riservata alle librerie installate con npm, come import PocketBase from "pocketbase".
